# research/

The project's research record: the reasoning behind the code, published with it. Ratings live in
`leaderboard/` (`tools/leaderboard.py show`), not here; a log cites a player's Elo at a commit, and
each network's behaviour report is in [`log/per_checkpoint/`](log/per_checkpoint/README.md).

## Start here

| file | |
|:---|:---|
| [`checkpoints.md`](checkpoints.md) | **which model to load** and what it is worth: current standings, designated bests, how to reproduce them |
| [`runs.md`](runs.md) | **the arm registry**: one row per arm — what it varied, budget, directory, outcome, writeup |
| [`questions.md`](questions.md) | **the question index**: one row per question, with the arms and the verdict |
| [`architectures_and_recipes.md`](architectures_and_recipes.md) | the A and R codes of run names and their flags (generated by `tools/scripts/run_codes.py` from [`run_codes.json`](run_codes.json)) |
| [`run_name_map.md`](run_name_map.md) | every pre-2026-10-07 run directory under its E-A-R-S name (generated) |
| [`method/measurement_pitfalls.md`](method/measurement_pitfalls.md) | read before trusting any number |

## Filing: by update discipline, not by topic

| directory | discipline | the question it answers |
|:---|:---|:---|
| [`log/`](log/README.md) | **append-only** | what did we try, and why do we believe it? Every measurement lands here first ([`method/bookkeeping.md`](method/bookkeeping.md)) |
| [`findings/`](findings/README.md) | **rewritten in place** | what is true now? Split into [`engine/`](findings/engine/README.md) (what the simulator does) and [`training/`](findings/training/README.md) (what a training choice is worth) |
| [`method/`](method/README.md) | living reference | how do we measure, name and record? |
| [`plans/`](plans/README.md) | forward-looking; becomes a log once run | what should we try next? `plans/PN` proposes, `log/PN_*` records |
| [`papers/`](papers/README.md) | static | what does the literature say? |
| [`archive/`](archive/README.md) | frozen | superseded ladders (E3, E4 plans), kept for history |

**The test when unsure:** if a statement here turns out wrong, do you *edit* it (→ `findings/`,
`method/`) or *correct it underneath* (→ `log/`)? Dead ends, retracted claims and failed predictions
stay in the log permanently; that is how "did we already try that, and why did we stop?" gets
answered. `findings/` states conclusions and links to the log; it never re-tells the experiment.

**Engine changes.** The owner's assumption: engine changes make old arms incomparable, but (after the
starred-events fix) do not change the relative effect of training approaches. Read
[`method/what_survives_an_engine_change.md`](method/what_survives_an_engine_change.md) before carrying
a number across a revision; the revisions themselves are
[`findings/engine/engine_revisions.md`](findings/engine/engine_revisions.md).

## Habits this record enforces

* **Register the prediction before the run** — what the probes and Elo should do, and which
  instrument will produce the number — in `plans/` or the arm's `--description`.
* **Index by question, not only by arm**: every result gets a row in [`questions.md`](questions.md).
* **A probe tests understanding only if its answer key is absent from the observation**, which here
  precomputes many per-country facts.
* **Split a file at about 400 lines**; a document nobody reads in one sitting stops being checked.
